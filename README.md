# SafeGate

Safety verification and conformity evidence for driverless industrial trucks.
**EN ISO 3691-4 · EN ISO 13849-1 · EN ISO 13855 · Regulation (EU) 2023/1230.**

A compiler from hazards to a technical file. Hazards, requirements, architectures
and test cases live in YAML next to the firmware. SafeGate derives Performance
Levels and runs falsification campaigns against a simulator or a HIL rig. It records
every run in a signed, chained evidence store, gates the release on declarative
policy, and generates the verification section of the technical file from that
store.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the design, [CHANGELOG.md](CHANGELOG.md)
for what 0.4.0 fixed in 0.3.0, and [docs/RESULTS.md](docs/RESULTS.md) for every
number quoted below.

## Results at a glance

The worked example is a fictional tow tractor, the T200, in two design revisions.
All figures are generated by `scripts/reproduce.py`.

**Rev A** (`examples/amr_project`, as first designed): 734 SIL runs, 4.7 s on 16
processes. All five test cases are falsified, each by a different real design gap:

| Test case | Worst margin | Cause found |
|---|---|---|
| TC-FIELD-001 | -2.635 m | field table sized without the person approaching during braking (ISO 13855 T) |
| TC-MUTE-001 | -3.77 s | no mute timeout |
| TC-SPEED-001 | -0.5925 m/s | zone speed supervised only inside the zone; late navigation enters too fast |
| TC-CROSS-001 | -0.548 m | struck when a person steps in about 1 m ahead at up to 2.0 m/s, once the non-safety slowdown is off |
| TC-CROSS-002 | -0.5423 m | the same from a cross aisle between racks |

The gate also blocks on PL d achieved against PLr e, on a reversing requirement with
no test case, and on missing HIL evidence.

**Rev B** (`examples/amr_project_revb`, after the findings): Category 4, a budget
for the worst floor, 1.0 m/s maximum speed, corrected fields, ramp monitoring and a
mute timeout. 1,262 SIL runs, 15.3 s. All six test cases pass. The tightest margins
are 0.056 m for a person stepping in at 1.0 m/s, 0.055 m/s at zone entry and
0.098 m for reversing. The gate still fails on exactly one rule, **R-EXEC-002**:
PL e functions need HIL evidence, and simulation is not allowed to stand in for it.

**Same campaign through Intel Labs scenario_execution:** when every rev B run is an
OpenSCENARIO 2 file executed by `scenario_execution` 1.5.0 in step-based simulation
mode, all 1,262 runs give the same verdict and bit-identical robustness as the
in-process runner. That path took 1,011 s on 32 processes against 15.3 s in-process;
`scenario_execution` parsing the OSC2 files for every run dominates.

**Through ROS 2:** with `--runner ros2`, each run is a ROS 2 Jazzy container in which
the world is a ROS 2 node recorded by `ros2 bag record`. All 72 executions of a
24-point campaign (three repeats each) match the in-process runner exactly.

**Evidence in object storage:** rev A with `--store s3://...` on MinIO wrote 742
manifest objects, gave outcomes identical to the filesystem store, and verified.

**Tamper evidence:** on the rev A store, deleting the 316 failing runs, flipping a
verdict, or editing the issued report all fail `safegate verify`. A chain rewritten
and re-signed with a new key passes plain verification and fails against the pinned
key or the published anchor ([docs/EVIDENCE.md](docs/EVIDENCE.md)).

## Install

Python 3.11 or newer.

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[sign,qmc,osc,s3,ros,dev]"
# osc = Intel Labs scenario_execution 1.5.0, s3 = boto3, ros = rosbags (reads rosbag2 without ROS)
```

## Use

```bash
P=examples/amr_project
safegate validate $P                     # referential integrity, STL parses, scenarios exist
safegate pl       $P                     # derive Performance Levels
safegate fields   $P                     # protective field sizing from the stopping budget

safegate keygen   ~/.safegate/ci-key     # signing key, kept outside the evidence store
safegate run      $P --store .evidence --build "$(git rev-parse HEAD)" \
                  --workers 8 --signing-key ~/.safegate/ci-key/signing.key
safegate gate     $P --store .evidence --policy $P/policy.yaml \
                  --trusted-key ~/.safegate/ci-key/signing.pub
safegate report   $P --store .evidence --policy $P/policy.yaml -o V-and-V.md \
                  --signing-key ~/.safegate/ci-key/signing.key
safegate anchor   --store .evidence -o anchor.json
safegate verify   --store .evidence --trusted-key ~/.safegate/ci-key/signing.pub \
                  --anchor anchor.json --report V-and-V.md
```

Exit codes: `0` pass · `1` a failing campaign, gate, PL determination or verification · `2` usage or load error.

Reproduce everything in docs/ (about 19 minutes with every optional backend on 32
cores, most of it the `scenario_execution` comparison; about a minute without them):

```bash
python scripts/reproduce.py --workers 16                      # SIL, tamper demo, benchmarks
python scripts/reproduce.py --workers 16 --osc --ros2 \
    --s3 s3://bucket/prefix                                   # plus scenario_execution, ROS 2, object storage
```

`--ros2` needs `docker build -f docker/ros2/Dockerfile -t safegate-ros:jazzy .`; `--s3`
reads the endpoint and credentials from the standard `AWS_*` environment.

## Runners

| `--runner` | Evidence tier | What executes |
|---|---|---|
| `sil` (default) | SIL | SafeGate's deterministic 2D closed loop: truck footprint, floor-friction braking, ray-cast safety scanners, field switching, safe-stop latency, zone supervision, muting timeout, fallible navigation ([docs/SIMULATOR.md](docs/SIMULATOR.md)) |
| `scenario_execution` | SIL | the same world, with each run an OpenSCENARIO 2 file executed by Intel Labs `scenario_execution` in step-based simulation mode |
| `ros2` | SIL | the same world as a ROS 2 Jazzy node in a container, recorded with `ros2 bag record` and extracted with a topic-to-signal mapping (`docker build -f docker/ros2/Dockerfile -t safegate-ros:jazzy .`) |
| `hil` | HIL only if the rig declares `physical: true` | a rig speaking `safegate-hil/1` ([docs/HIL_PROTOCOL.md](docs/HIL_PROTOCOL.md)); an emulator is included for contract tests and can never produce HIL evidence |
| `null` | SIL | closed-form point-mass smoke path |

## What it enforces

| | |
|---|---|
| **Performance Level** | derived from the architecture on every run, never asserted. CCF below 65 on Category 3 invalidates the determination rather than downgrading it. |
| **Traceability** | every hazard to a requirement to a test case, checked as graph reachability |
| **Falsification** | STL robustness as the objective; boundary, Sobol and simulated-annealing phases |
| **Margin** | a pass below the policy's margin floor (20 mm, 0.02 s or 0.02 m/s in the examples) is a major R-MARGIN-001 finding |
| **Determinism** | five-hash pinning and SHA-256 seeds; a non-reproducible result is `FLAKY`, a blocker |
| **No credit for non-safety layers** | crossing tests sweep the warning-field slowdown off as well as on |
| **Tamper evidence** | append-only chained manifest, content-addressed blobs, signatures checked against pinned keys, anchors published outside the store, report digest in the chain; filesystem or S3-compatible object storage with conditional writes |
| **Evidence tier** | tier comes from the runner; PL d/e obligations need HIL or above |
| **Same evidence, same design** | evidence produced against other design data or another build is a blocker |
| **ML in the safety path** | blocked from self-declaration: Regulation (EU) 2023/1230 Annex I Part A requires a Notified Body |

## Tests

```bash
ruff check src tests scripts
pytest -q
```

The suite includes regression tests for each 0.3.0 defect and for each defect an
independent review found in the 0.4.0 work, bit-identical parity
between the in-process runner and `scenario_execution` for all six scenario families,
cross-process determinism, and the HIL contract.

## Limits, stated up front

- **Falsification is not proof.** No counterexample found is evidence, not a guarantee.
- **The simulator is a model.** It leaves out tyre slip, steering, sensor noise and
  reflectivity, pedestrians who react, and controller faults. SIL results support the
  design argument; they do not discharge physical verification (R-EXEC-002).
- **Assumptions are inputs.** The ODD boxes (for example `entry_gap >= 1.0 m`) and the
  stopping budget are project data that SafeGate checks for consistency, not truths it
  establishes.
- **Not production-ready.** HIL has a protocol, client and emulator but no physical
  rig; the ROS 2 path is exercised with SafeGate's own plant node, not Gazebo, Nav2 or
  `scenario_execution_ros`; the object-storage backend is tested against MinIO, not
  AWS S3; the PL route is the simplified Annex K route.
- **Standards texts are not reproduced.** Only engineering relationships are
  implemented; clause references are project data.
